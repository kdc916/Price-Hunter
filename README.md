# Price Hunter v0.6.0 — 사진 인식부터 시세·수익까지 한 화면

## 핵심 변경 (2026-10-18)
- **적립금·포인트·캐시백·할부금·배송비·할인액**은 화면에 `원`이 붙어도 구매가로 채택하지 않습니다.
- 판매가와 적립 포인트가 한 줄에 나올 때 **각 가격 후보 앞뒤 문맥을 분리**합니다.
- 가격 단위 `원`, `만원`, `천원`, `₩`이 없는 콤마 숫자는 구매가에 넣지 않습니다. OCR 손상으로 가격 단위가 사라지면 자동 선택을 보류합니다.
- 할인율 `11%`은 가격으로 선택하지 않되 `11% 3,109,090원`, `할인가 3,109,090원`은 일반 판매가로 허용합니다.
- 할인 전 가격·조건부 혜택가·판매가를 별도로 구분합니다.
- 둘 이상의 비슷한 판매가 후보가 충돌하면 **자동 입력과 수익 계산을 보류**합니다. 신뢰도가 낮은 후보도 직접 확인해야 입력할 수 있습니다.
- 결과 영역에 구매가에서 제외한 적립·포인트·할인액을 명시적으로 표시합니다.
- 무과금 HTML/PWA, 기존 로컬 저장 데이터 유지, PWA 캐시 v032 갱신.

# Price Hunter v0.3.2 — 실사진 가격·모델 인식 개선

**유료 API 없는 HTML/PWA**. 상품 스크린샷·가격표 사진 한 장을 입력해 OCR로 상품명과 판매가를 찾고, 구글 공개 검색 페이지에서 실제 시세를 직접 검증하고 저장하는 도구입니다.

## 이번 패치

- 기존 **제품/가격 따로 촬영 불필요**: 단일 사진/스크린샷/붙여넣기.
- OCR 품질 저하 시 **전체 이미지 → 고대비 이미지 → 상단 집중 이미지**, 최대 3단계 재인식. 조건을 만족하면 조기 종료해 과도한 처리 방지.
- 여러 OCR 결과의 **상품명과 가격 필드를 각각 선택**, OCR 결과를 통째로 덮어쓰지 않음.
- **판매가 / 할인 전 가격 / 로그인·쿠폰 등 조건부 가격 / 포인트 적립금 / 할부·배송비** 구분.
- 사용자 삼성 폴드 스크린샷 기반 문자 예제: `갤럭시 Z 폴드8 5G 256GB 자급제`, **표시 판매가 1,993,540원**, 할인 전 **2,208,300원**, 적립 포인트 **20,170P**는 판매가에서 제외. 원본 이미지는 저장소에 포함하지 않음.
- 제한된 OCR 교정 (예: `갤럭시 7 폴드856 25668` → `갤럭시 Z 폴드8 5G 256GB` 후보), 단정 대신 확인 경고. 제조사 SKU(`SM-...`)와 마케팅 제품명(`Fold8`) 분리.
- 기존 LG TV 가격 구분, 폴라로이드/카메라, 분석 기록 및 무료 검색 링크 유지.
- `localStorage` 기존 `price-hunter-0.1.0` 키 보존. 데이터 삭제·마이그레이션 없음.

## 실행

1. GitHub Pages에서 HTTPS로 접속하거나 로컬 HTML을 열어 실행합니다.
2. `사진 찍기 · 스크린샷 선택`에 **사진 한 장**을 넣거나 Ctrl+V로 붙여넣습니다.
3. 최초 Tesseract.js 한국어·영어 OCR 다운로드는 네트워크가 필요합니다. 브라우저 내부에서 이미지를 인식합니다.
4. **상품명, 판매가**를 확인하고 잘못된 경우 직접 수정합니다. OCR은 정확도를 100% 보장하지 않습니다.
5. 동일 모델로 **구글 `site:` 검색**을 열어 중고나라·당근·번개장터 등의 **공개 색인 매물**을 확인합니다.
6. 실제 매물과 동일 모델 여부를 확인한 뒤 기록합니다. 일정 수 이상의 검증된 가격 기록이 있어야 중고 예상가 및 ROI를 계산합니다.

## 중요한 한계

- AI 비전 분류기는 아닙니다. **Tesseract.js OCR + 결정적 분석·재처리**를 이용하며, 모델 코드가 보이지 않으면 SKU는 `미확인`입니다. 외형으로 정확한 모델을 단정하지 않습니다.
- 실제 스크린샷의 한 번의 문자 인식은 해상도·번짐·배경색에 따라 달라집니다. 교정한 상품명은 원본과 반드시 대조해야 합니다.
- 자동으로 중고 가격 전체를 가져오거나 과거 거래완료 금액을 보장하지 않습니다. 구글 검색 결과는 색인에 따라 누락될 수 있습니다.
- **포인트 적립·할부 안내·쿠폰 조건부 가격·배송비**를 기본 구매가에 합산하지 않습니다.
- 수집·저장한 데이터만 통계에 사용하며, 가정 기반 ROI는 실현 수익이 아닙니다.
- PWA는 GitHub Pages 등 HTTPS 환경에서만 설치·서비스워커 기능이 동작합니다. `index.html`을 단독 열 경우 필요한 JS 파일도 같은 폴더에 있어야 합니다.

## 파일

- `index.html`: 모바일 우선 인터페이스
- `app.js`: OCR 재시도/프리프로세싱, 상품 확인, 분석 저장
- `screenshot.js`: 상품·가격 구분, OCR 결과 병합
- `core.js`: 동일 모델 비교, 매물/통계, 수익 계산 (기존 유지)
- `sw.js`: 버전된 캐시
- `tests/`: 회귀 검증 테스트
- `HANDOFF_CUMULATIVE.md`: 누적 인수인계/후속 로드맵

제3자 API 사용료 없음. 공개 검색 결과를 대량으로 무단 수집하거나 유료 API를 우회하지 않습니다.

- 검색결과 카드에서 직접 링크를 열어 시세를 검증하고 명시적으로 기록할 수 있습니다. **검색 색인 가격은 확정 거래가가 아니며, 예상 순이익 통계에 자동 합산하지 않습니다.** 복수 가격이 발견되면 가격을 비워 둡니다.

## v0.5.1 — Adaptive Region OCR / 한국어 OCR 엔진 연구
- 앱의 실제 OCR 엔진은 현재 **Tesseract.js 6**입니다. **PaddleOCR PP-OCRv5 Korean**은 후속 이중 엔진 후보이며 이번 패치에 구동 완료됐다고 표기하지 않습니다.
- 수평형 카드/데스크톱 2열/세로형 모바일에 따라 금액·상품명이 있는 영역을 별도로 확대합니다. `ocr-regions.js`에서 기하학적 크롭 후 PSM 6/11 인식, 최후 전체 고대비 검사.
- 판매가 후보가 있다고 첫 OCR에서 조기 종료하지 않고, **첫 번째 가격 영역은 반드시 한 번 더 검사**합니다. 취소선 정가를 유일한 가격으로 잘못 판단할 위험을 줄입니다.
- 할인 전 가격이 명시되지 않아도 `35%`와 `1,840,000원 → 1,190,000원`의 실제 할인율이 일치하고 가격들이 서로 다른 OCR 행에 존재할 때만 기존 높은 금액을 정가 후보로 분리합니다. 같은 행에 근거 없이 여러 가격이 있으면 기존대로 자동 입력하지 않습니다.
- 로보락 S9 MaxV Ultra 화면의 상품명·금액 인식 문제는 실제 업로드된 샘플을 대상으로 Tesseract 5 CLI에서 테스트했습니다. 전체 OCR (`--psm 6`)에서는 `1,190,000` 뒤의 원 단위가 손실되었으나 상품 오른쪽의 가격 영역을 분리한 `--psm 6`에서는 `1,190,000원`을 읽는 결과가 나왔습니다. 이는 로컬 엔진의 단일 샘플이며 모바일 Tesseract.js 정확도 수치가 아닙니다.
- 프레임 분석 결과의 정확도는 모델·OCR 원문·조명·화면 레이아웃에 영향을 받습니다. 실기기 E2E 테스트는 별도 필요.
- 무료 PaddleOCR 조사: 공식 브라우저 SDK `@paddleocr/paddleocr-js`(Apache-2.0), `korean_PP-OCRv5_mobile_rec` 약 14 MB(한국어·영어·숫자). 검출·인식 ONNX 모델과 WASM 런타임 다운로드/배포, 한국어 모델 아카이브와 번들링의 실제 검증이 필요하여 검증 없는 자동 탑재를 보류.
- 후속: PaddleOCR Browser SDK + Korean model ONNX/WebGPU/WASM 실제 동작 확인 → 10~30종 실제 스크린샷 가격 정확도·처리 시간·메모리 벤치마크 → Tesseract와 품질 비교 및 안전한 fallback.
- 자료: https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/inference_deployment/cross_platform/browser.en.md ; https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md
